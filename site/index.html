LabBridge

面向二甲及乡镇卫生院的检验数据桥接 Demo。把仪器数据与纸质报告汇入统一记录，全程脱敏、留痕、可追溯。

零第三方运行时依赖 纯 Python 标准库 MIT 许可 主程序 3231 行 + 15 模块 7117 行 tkinter GUI · 11 页签

它解决什么问题

基层检验科有三个绕不开的现实，本 Demo 逐一给出了技术答案。

轨道 A · 直连

仪器有数据，但取不出来

实现 ASTM E1381 / E1394 只读接收端，直接接管仪器吐出的数据流，无需厂商配合开放接口。

轨道 B · 兜底

老设备没接口，只能手抄

拍照 OCR 抽取 + 人工确认。不改造任何设备即可录入，把人的复核留在流程内而非流程外。

合规

数据必须留在院内

全程本地处理，不上云、不外传。5 条红线以代码常量形式强制执行，违反即拦截。

审计

要能说清每一步是谁做的

审计日志采用哈希链结构，改动或删除任意一条都会立刻断链并被检出，而非依赖流程承诺。

核心设计取舍

这几处是本项目与一般练手项目的分界线。

审计日志用哈希链，不是"记个文件"

每条日志带 prev_hash。改任意一条、或删掉中间任意一段，校验都会立刻断链。这是"可追溯"能站得住的技术前提。

红线在代码里，不在文档里

数据不出院、禁止明文留存 PII、无审批不处置等 5 条红线，以 labbridge_gate.py 中的 REDLINES 常量强制执行。

零第三方依赖是主动选择

基层环境常无稳定外网与运维能力。零依赖意味着无供应链风险、无许可费用、无版本冲突——代价是 YAML 解析、MCP 协议、SAS XPORT 解析都需自行实现。

第三方许可逐一审查

社区轮子很多，但授权未必允许商用。选型清单逐项标注"可直接用 / 可重写 / 重写也没用"的判定与依据。

模块结构

主程序负责 GUI，code/ 下 15 个模块为业务核心，不依赖 tkinter 与任何 Windows API，可整块移植到服务端。

模块职责
labbridge_astm.py轨道 A：ASTM E1381 / E1394 只读接收端
labbridge_ocr.py轨道 B：拍照 OCR 抽取与人工确认
labbridge_deid.py脱敏与访问控制引擎
labbridge_screen.py审核规则引擎与熔断检测
labbridge_auditlog.py审计日志中间件（哈希链防篡改）
labbridge_evidence.py证据包 / 资产包 / 验收断言 / CAPA
labbridge_gate.py红线自检 · 阶段门 · 审批门
labbridge_pdca.pyPDCA 质量工具集（SPC、FMEA、控制图等）
labbridge_config.py配置层（含 YAML 子集解析器）
labbridge_report.py证据报告生成器（docx）
labbridge_docparse.py文档解析管线
labbridge_mcp.pyMCP Server（零依赖实现）
labbridge_nhanes.pyNHANES 真实公开数据回放
labbridge_apibridge.py外部接口对接桥（ASTM / OCR / LIS / LLM）
labbridge_demo.py端到端 Demo 编排器

快速开始

没有依赖安装步骤——这是本项目刻意坚持的约束。

git clone https://github.com/lichengze9015/LabBridge.git
cd LabBridge
python labbridge_v2_app.py

# 验证安装
python test_v240.py
首次运行会在同级目录生成 v2_data/（日志、账户、证据包）。DEMO 账户：工程师 1111 · 组长 2222 · 主任 3333 · 检验员 4444。
