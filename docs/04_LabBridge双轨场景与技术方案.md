# 04 · LabBridge 双轨场景与技术方案

> 项目代号：LabBridge（面向二甲及乡镇卫生院的检验数据桥接）
> 文档集版本：V4.2 ｜ 编制日期：2026-10-30
> 对应软件版本：V2.5.2 ｜ 对应封包：`LabBridgeV4`
> 适配标准：ISO 9001:2026、ISO/IEC 42001:2023，部分参考 ISO 13485:2016
> 本文职责：定义双轨（ASTM 旁路 / 拍照 OCR）落地场景、三层技术架构与 Demo 验证事项

---

## 一、Demo 定位：不做「系统」，做「桥」

核心判断：不做「更好的 LIS」或「替代原厂的 AI 中间件」，而是在原厂 LIS 与仪器之间、或纸面与系统之间，占据原厂不愿意做、但基层极度需要的「接收与提取」位置。

## 二、真正的插入点

ASTM E1381/E1394 是绝大多数临床检验仪器（Sysmex、Roche、Abbott、Beckman Coulter、Mindray 等）原生支持的结果上传协议，而原厂 LIS 中间件通常只处理自己生态内的仪器，或对第三方接入设置门槛。

第三方可以在**不触碰原厂 LIS、不要求原厂开放接口**的前提下，作为一个仅接收（receive-only）的 ASTM 端点，直接从仪器串口或 TCP 连接上「旁路」抓取结果。

开源包 `labmcp-astm-lis` 已验证该模式的可行性（小型 ASTM 接收端：确认帧、校验校验和、重组消息、默认脱敏）。**V2 起 ASTM 只读接收端已自研（`labbridge_astm.py`），开源包降级为可选适配器**（供应链单点依赖风险见 07 号文档 R-10）。

**技术底座不需要硬件，一台普通电脑或边缘盒子即可运行。**

## 三、Demo 要验证的三件事

| 验证项 | 具体内容 | 成功标准 | V4 状态 |
|---|---|---|---|
| 技术桥接可行性 | 从至少 1 台真实基层仪器（血球仪或生化仪）旁路抓取 ASTM 结果，不经过原厂 LIS | 连续抓取 ≥ 50 份标本，结果完整率 ≥ 99%，脱敏字段正确 | 合成数据链路 PASS；**未接真实仪器** |
| 轻量 AI 增值 | 在抓取结果之上跑一个最小 AI 审核规则（异常标志识别、危急值预筛、重复结果提示） | 对 ≥ 100 份历史结果回溯，AI 标记的异常与人工判断一致率 ≥ 95% | 规则引擎 PASS；一致率 **unmeasured**（须人工复核） |
| 双轨可复制性 | 同一套后端，前端分别适配「有仪器无有效 LIS」的二甲场景和「纯手抄无仪器」的乡镇场景 | 二甲侧 ASTM 链路跑通；乡镇侧拍照 OCR 链路跑通，各完成 1 个真实场景 POC | 两轨代码均已落地；**未见场 POC** |

## 四、轨道 A：二甲场景 —— 旁路 ASTM ＋ 轻量 AI 审核

**适用对象**：有检验仪器、有原厂 LIS 但功能老旧或不开放、人员不足以逐份审核的基层二甲。

**技术路径**：

1. **旁路接入**：在仪器与现有 LIS 的连接链路上插入 ASTM 接收端，仅接收、不干扰原有传输；仪器仍向原厂 LIS 发送结果，桥接层同时收到一份副本。
2. **脱敏与清洗**：接收端在落盘前对患者身份字段做 redact，保留患者 ID、性别、检测项目、结果值、异常标志和仪器报警注释。
3. **最小 AI 审核**：不做全量自动审核，只做三件事——异常标志聚合（仪器 H/L 标志与参考区间不一致的结果标出）、危急值预筛（按预设阈值标记）、重复/矛盾结果提示（同一患者短期内相同项目结果显著漂移）。输出**「待关注列表」**，不替代签字。
4. **效果对照**：回溯性跑一批历史结果，与人工实际审核记录比对，计算「AI 标记但人工未关注」和「人工关注但 AI 未标记」两个方向的遗漏率。

**Demo 价值**：不要求医院更换任何硬件，不要求原厂配合，ASTM 协议是公开标准；Demo 成本极低，验证周期可压缩到 2—4 周。

**接入新机型前必须确认的三件事**（写在 `labbridge_astm.py` 内，V4 保留原文）：

1. **字符集** —— 国内仪器多发 GBK，用 `LABBRIDGE_ASTM_CODEC=gbk` 覆盖，否则中文姓名变问号。
2. **P 记录字段位** —— E1394 实机存在两种习惯（P.3/P.5/P.7/P.8 与 P.4/P.6/P.8/P.9）。本模块容错读取（按形态匹配取第一个合理值），接入新机型须用真实报文确认。
3. **O 记录标本号** —— 标本号在 **O.3** 而非 O.2；取错会让所有标本塌缩成一份（调试中实际踩过：50 份标本被读成 1 份）。

另外：**帧尾判定不能「见到第一个 CR 就收帧」**——E1394 记录分隔符本身就是 CR，真正的帧尾形态是 `ETX/ETB + 2 位校验和 + CR [LF]`。

## 五、轨道 B：乡镇场景 —— 拍照 OCR ＋ 云端最小闭环

**适用对象**：无有效 LIS、结果大量手抄、甚至没有稳定仪器的乡镇卫生院和村卫生室。

**技术路径**：

1. **拍照提取**：手机拍摄手写申请单、仪器屏幕或纸质报告，OCR ＋ 结构化抽取输出检验项目、结果值、异常标志。现有工具在拍摄质量较高的场景下准确率可到 95%—100%，拍照后 2 秒提取关键信息，效率为手动录入的 3 倍。**已落地为「后端适配 ＋ 人工确认队列」的半自动模式**（见第七节）。
2. **脱敏后上云**：在手机端或本地边缘完成脱敏（姓名、身份证号、地址替换为假名化 ID），云端只接收脱敏后的结构化数据。**原始图像和可识别信息不离开本地。**
3. **最小输出**：不追求「生成完整检验报告」，只输出结构化结果记录（让「手抄」变成可查询的数据）和异常提示（对超出参考区间或与历史趋势矛盾的结果给出简单标记）。
4. **与轨道 A 共享后端**：AI 审核规则、异常判定逻辑、数据模型完全复用，只是前端输入从 ASTM 流变成 OCR 流。

**Demo 价值**：乡镇场景几乎没有竞品在做「真正零系统前提」的 AI 落地；跑通「拍 100 张单子 → 结构化 → 异常提示 → 村医可用」即是可复制性极强的故事。

## 六、技术架构：三层，尽量「薄」

| 层级 | 组成 | 关键约束 |
|---|---|---|
| 接入层（不碰原厂） | 轨道 A：ASTM 旁路接收（串口/TCP）；轨道 B：手机拍照 → 端侧/本地 OCR → 脱敏 | 不碰原厂，只读旁路，不向仪器发送查询或指令 |
| 桥接与 AI 层（核心资产） | 结果标准化（ASTM 记录/OCR 结构化 → 统一模型）；脱敏引擎（默认 redact，可审计）；轻量审核规则引擎（异常标志、危急值、趋势漂移）；可选调用云端 LLM 做报告解读（仅对脱敏文本） | AI「薄」到可解释，规则可逐条追溯 |
| 输出层（极简） | 二甲：浏览器/桌面端「待关注列表」；乡镇：手机端结构化结果 ＋ 异常提示；可选按需回传原厂 LIS（不强制） | 不给基层增加新系统负担 |

**关键约束**：

- 不部署本地服务器（桥接层可运行在一台普通电脑、边缘盒子或云端容器中）；
- 不要求原厂 LIS 改造（二甲侧 ASTM 旁路是只读的，不影响原传输）；
- AI「薄」到可解释（Demo 阶段不做黑箱模型，规则引擎 ＋ 可选 LLM 辅助解读，规则可逐条追溯）。

## 八、双轨对照速查

| 维度 | 轨道 A（二甲） | 轨道 B（乡镇） |
|---|---|---|
| 输入源 | 仪器 ASTM E1381/E1394 串口/TCP 旁路 | 手机拍照 → OCR |
| 前置条件 | 有仪器、有老旧/封闭 LIS | 无 LIS、手抄为主 |
| 脱敏时机 | 接收端落盘前 redact | 手机端/本地边缘 redact，图像不出本地 |
| 上云内容 | 脱敏结构化字段 | 脱敏结构化字段 |
| AI 动作 | 异常标志聚合、危急值预筛、趋势漂移 | 同左（规则复用） |
| 输出形态 | 待关注列表（桌面/浏览器） | 结构化记录 + 异常提示（手机） |
| 验证周期 | 2—4 周 | 拍 100 张单子即可验证 |
| 复用关系 | 共享后端：审核规则、异常逻辑、数据模型完全一致 | 同左 |

## Agent Demo 落地映射

这份文档直接定义 Agent 的**工具集**。5 个工具职责单一、均可独立测试：

| 技术组件 | Agent 工具 | 输入 → 输出 | 备注 |
|---|---|---|---|
| ASTM 旁路接收 | `astm_listen(source)` | 串口/TCP → 原始 ASTM 消息 | 只读，禁止下发指令；记录接收时间戳 |
| 结果标准化 | `normalize_result(raw)` | ASTM/OCR 结构 → 统一结果模型 | 统一模型字段：患者伪 ID、性别、项目、结果值、单位、参考区间、异常标志、仪器注释 |
| 脱敏引擎 | `deidentify(record)` | 原始记录 → 脱敏记录 | 默认 redact；脱敏后做正则回扫校验 |
| 轻量审核规则引擎 | `screen_abnormal(results)` | 结果集 → 待关注列表 | 三条规则：异常标志聚合、危急值阈值、趋势漂移；规则外置为配置文件 |
| OCR 抽取（轨道 B） | `ocr_extract(image)` | 图像 → 结构化字段 | 半自动，必须人工一键确认 |

**审核规则引擎外置配置 `config/screening_rules.yaml`（R1/R2/R3 已按此 Schema 实现于 `labbridge_screen.py`）：**

```yaml
rules:
  - id: R1
    name: 异常标志聚合
    desc: 仪器 H/L 标志与参考区间不一致
    action: flag
  - id: R2
    name: 危急值预筛
    desc: 按预设阈值标记
    params: {thresholds: "critical_values.yaml"}
    action: flag_urgent
  - id: R3
    name: 重复/矛盾结果提示
    desc: 同一患者短期内相同项目结果显著漂移
    params: {window_days: 7, drift_pct: 30}
    action: flag
output:
  form: 待关注列表
  forbidden_wording: ["已审核", "已签发", "结论为"]
```

**「薄」是刻意的设计选择**：规则引擎为主、LLM 为辅，每条标记都能回答「为什么」，这在基层建立信任比准确率数字更重要。
