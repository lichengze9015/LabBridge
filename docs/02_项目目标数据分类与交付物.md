## 一、数据分类定义

| 数据类别 | 定义 | 典型内容（含场景映射） |
| --- | --- | --- |
| 公共数据 | 可对外公开，无企业业务信息 | ISO 标准原文、公开行业指南、公开培训案例、ASTM E1381/E1394 公开协议规范 |

## 二、项目总目标

搭建 ISO 体系约束下的 AI Agent 治理 Demo。

在医疗检验数据桥接场景中，验证「从基层仪器旁路抓取或拍照提取检验结果，脱敏后由轻量 AI 做审核提示」的双轨路径；公共/非敏感场景可选用公共大模型；Demo 受控接入真实敏感数据完成验证，输出实测结论，指导 IVD/制造业 AI＋ISO 正式项目落地、风险判定与管控策略。

全程**风险前置评估、分级数据上线、人在回路**，留存完整可追溯证据链，评估不同大模型底座收益、风险与适用边界。

## 三、分层可测量目标（含量化基线）

> 量化基线优先取自具体落地场景的验收标准；未给定的通用性目标以「建议值」标注，正式立项时按场景校准。
> **V4 执行状态**：下表「V4 实测」列记录当前封包的实际状态。**unmeasured = 未测量**，严禁以机器判据代填。

### 一级目标 1：公共、非敏感数据场景试点验证

- 公共大模型可选，可更换底座横向对比效能风险；
- 构建离线解耦知识库，搭建 Agent 工作流，完成文档检索、条款比对、内审初稿生成；
- 导入非敏感数据（脱敏检验字段），测试文档归集、缺陷识别、日志留痕；
- 记录效率、幻觉概率、条款匹配准确度、日志完整性，记录底座切换差异；
- 识别模型幻觉、RAG 检索错误、提示词注入、版本管理缺陷，输出风险清单与 CAPA。

**量化基线**：条款匹配准确度 ≥ 90%（建议值，按场景校准）；脱敏正确率 100%（场景标准）；全程日志留痕率 100%。
**验收**：两类场景流程闭环；输出多底座对比分析报告；知识库、Agent 配置离线归档。
**V4 实测**：脱敏正确率、日志留痕率由 `test_v240.py`（46/46）与模块自检（15/15）覆盖 **PASS**；条款匹配准确度 `unmeasured`（需人工复核样本集，不得用机器判据代填）。

### 一级目标 2：制定敏感数据接入专项风险管控方案与准入边界（风险策划前置）

- **识别风险**：数据泄露、模型留存数据、会话污染、敏感信息外溢、幻觉生成虚假体系证据造成外审不符合项。
- **制定管控**：字段掩码、会话隔离、访问白名单、会话自动清理、二次复核、输入输出过滤。
- 开展风险矩阵评估，确定高风险控制手段与残留风险接受准则；
- 制定底座选型规则，判定公共大模型是否适用于敏感场景或是否需要私有化部署。

**验收**：《敏感数据接入专项风险评估报告》评审通过；准入边界、管控流程、应急处置文件定稿。
**V4 实测**：报告生成器已落地（`labbridge_report.py`，自检 PASS）；风险登记表中残余风险多数仍为 `待评估`，属 11 号文档第九章待办第 5 项，V4 未关闭。

### 一级目标 3：Demo 受控引入真实敏感数据实测，输出落地结论（核心目标）

- 全套管控措施部署评审通过后，小范围受控导入敏感数据，权限管控、全链路日志留存；
- **人机协同**：Agent 完成归集、预审、初稿；敏感输出人工逐条终审，保留审核痕迹；
- 采集实测：幻觉情况、泄露风险、检索准确度、管控机制有效性、工作流稳定性；评估模型底座得失、残留风险、适用边界。

**量化基线（场景标准）**：连续抓取 ≥ 50 份标本、结果完整率 ≥ 99%、脱敏字段正确；对 ≥ 100 份历史结果回溯，AI 标记异常与人工判断一致率 ≥ 95%。
**验收**：敏感场景试运行闭环；实测、审核痕迹完整；输出《敏感场景 AI 应用结论报告》，指导正式项目选型、流程、风险管控。
**V4 实测**：**未达成，且标记为 unmeasured**。NHANES 公开数据回放已跑通（`LabBridge_NHANES.exe` + 《真实数据测试报告_NHANES血常规.md》），但那是公开脱敏数据，**不等于目标 3 的受控敏感数据实测**。`abnormal_agreement` 与 `clause_match_accuracy` 两项在 `acceptance.yaml` 中保持 `unmeasured` 标记；「规则标记 vs 区间判据」重合度（0.54）单列为**待人工裁定项**，不当作一致率交付。**

### 一级目标 4：业务资产持续解耦，实现跨底座迁移

知识库、评审规则、提示词模板、风险清单离线冷备份物理隔离；Agent 工作流可导出迁移，业务资产脱离平台可复用，规避平台绑定沉没成本。
**验收**：全套业务资产独立归档，可脱离当前模型底座使用。
**V4 实测**：已达。`export_asset_pack()` 实现 zip + manifest 逐文件 SHA-256；V4 交付包本身即为「源码 + spec + 受控配置 + 文档」同包结构，可在任何装有 Python 3.14 的机器上重新构建。

### 一级目标 5：Demo 项目完整完成 PDCA 循环

- **Plan**：场景划分、底座规则、敏感数据风险策划、目标定义；
- **Do**：公共/非敏感测试，受控开展敏感数据实测；
- **Check**：内审、缺陷识别、得失评估、残留风险判定；
- **Act**：输出改进措施，输出可移植正式项目的持续改进机制。

**验收**：完整 PDCA 证据包，包含 CAPA 整改记录，满足 ISO 内审证据要求。
**V4 实测**：已达。`LabBridge_PDCA.exe` 36 工具自检 **36/36 PASS**（P 8/8、D 11/11、C 8/8、A 9/9）；每次运行输出独立时间戳目录，含 `06_PDCA测试图谱汇总.html`，不覆盖历史。

## 四、目标执行先后顺序

| 阶段 | 内容 | 底座策略 |
| --- | --- | --- |
| 阶段一 | 公共数据测试，验证基础 Agent 流程 | 公共大模型可选 |
| 阶段二 | 非敏感内部数据测试，验证业务文档适配，积累风险识别经验 | 公共大模型可选 |
| 阶段三 | 敏感数据接入专项风险评估，审批管控方案 | — |
| 阶段四 | 受控接入真实敏感数据实测，采集运行数据输出结论 | 依据前期测试与风险评估决策 |

> **顺序即红线**：阶段三的评审未通过，不得进入阶段四。软件上由 `labbridge_gate.StageGate` 硬拦截，**默认状态下阶段四是阻断的**（这是设计而非缺陷，证明门禁真的会拦）。

## 五、项目红线（核心约束）

1. 敏感数据必须等风险控制措施部署评审完成后才可接入，**禁止提前加载**。
2. 无论何种模型处理敏感数据，坚持人在回路，高风险判定、最终结论**由人终审**。
3. **全程留痕**：数据导入、模型调用、输出、人工修订，保存时间戳、操作员、版本记录，满足 ISO 证据链。
4. Demo 敏感场景结论作为正式项目决策依据，但 **Demo 本身不等于生产级上线系统**。
5. 试点验收后扩大范围**必须重新独立立项、新建 POC**，禁止原项目直接扩容。

> V3 原文为 4 条；第 5 条来自 00 号总纲第五节红线列表，V4 归并至此以消除两处表述不一致。五条的实质内容与原 1–4 条一致，无新增承诺。

## Agent Demo 落地映射

这份文档是 **Demo 的验收脚本来源**。

| 内容 | Agent 落点 | 实现建议 |
| --- | --- | --- |
| 数据分类表 | 分类器标签集 | `data_class: public / internal / sensitive` 三值枚举，字段级打标，作为下游策略输入 |
| 量化基线 | 自动化断言 | 可执行校验：`completeness >= 0.99`、`abnormal_agreement >= 0.95`、`log_coverage == 1.0`、`deidentify_accuracy == 1.0` |
| unmeasured 标记 | 反伪造约束 | **断言不得把 unmeasured 项当作已通过**；缺失人工判据时必须输出「待人工裁定」而非估算值 |
| 四阶段顺序 | 工作流阶段门 | `stage_gate`：阶段三「风险评估通过」为阶段四前置条件，未过则工作流阻塞 |
| 项目红线 | 硬约束清单 | 5 条红线做成启动自检项，任一不满足则拒绝启动敏感数据处理 |
| 交付物清单 | 证据包目录 | 直接映射为证据包目录树（见 08 号文档） |
| 脱敏正确率 100% | 强校验 | 脱敏后正则回扫（姓名/身份证/电话/地址模式），命中即告警并阻断输出；V3 已修复 miniyaml 双引号转义导致的回扫失效，「零依赖环境的等价性校验」纳入验收 |

**受控断言文件 `config/acceptance.yaml`：**

```yaml
baseline:
  clause_match_accuracy:   {op: ">=", value: 0.90, note: "建议值，按场景校准；实测标记 unmeasured"}
  deidentify_accuracy:     {op: "==", value: 1.00}
  log_trace_coverage:      {op: "==", value: 1.00}
  sample_capture_min:      {op: ">=", value: 50}
  result_completeness:     {op: ">=", value: 0.99}
  abnormal_agreement:      {op: ">=", value: 0.95, note: "实测标记 unmeasured，须人工复核"}
stage_gate:
  sensitive_data_load:
    requires: ["risk_assessment_approved", "control_measures_deployed"]
```
